# Hugging Face Models Assets on R2 for Cloudflare Workers

> 🌐 Language / Ngôn ngữ: **English** | [Tiếng Việt](README.vi.md)

A Cloudflare Worker that stores and serves Hugging Face model-card snapshots
on Cloudflare R2. Objects are immutable by key; uploads are authenticated with a
publisher token and verified by SHA-256 content digest. This Worker is
designed to sit behind the [Huggingface Stream Proxy](https://github.com/dangkhoa2016/Huggingface-Stream-Proxy-Cloudflare-Worker)
through a Cloudflare Service Binding.

```text
Client
  -> Stream Proxy Worker (/assets/*)
  -> ASSET_SERVICE (Service Binding)
  -> This Worker
  -> Cloudflare R2
```

## Features

- Stores model-card snapshots as immutable R2 objects keyed by commit hash and
  path.
- Authenticates uploads with a bearer `PUBLISH_TOKEN` and constant-time token
  comparison.
- Validates `X-Content-SHA256` content digest on every upload and enforces an
  optional `MAX_UPLOAD_BYTES` limit.
- Returns `409 Conflict` when the same key is uploaded with different content;
  same-digest uploads are idempotent and return `200` without touching R2.
- Streams `GET` responses directly from R2 without buffering; supports byte
  `Range` requests, `If-Range`, and HTTP conditional requests including
  `If-Match`, `If-Unmodified-Since`, `If-None-Match`, and
  `If-Modified-Since` with full entity-tag wildcard, list, and weak/strong
  comparison semantics.
- Returns `Content-Range` on partial responses (`206`), `Accept-Ranges: bytes`,
  and `Last-Modified` on all reads.
- Sets immutable `Cache-Control` (`public, max-age=31536000, immutable`) on
  stored objects.
- Returns CORS headers (`Access-Control-Allow-Origin: *`) on all responses.
- Rejects malformed asset paths, encoded separators (`%2F`, `%5C`), and
  missing path segments.
- Validates commit hashes as 40-character lowercase hex strings.

## Security model

Uploads require a `Bearer` token matching the `PUBLISH_TOKEN` secret. Token
comparison uses constant-time equality to prevent timing attacks. The Worker
never stores or exposes `PUBLISH_TOKEN` in responses.

Content integrity is enforced by `X-Content-SHA256`:
- The digest must be a 64-character lowercase hexadecimal SHA-256 hash.
- The `Content-Length` header is required to bound the upload.
- Uploads exceeding `MAX_UPLOAD_BYTES` are rejected with `413`.

Object keys are immutable once written. A second upload with the same key and
same digest is idempotent (`200 already_exists`). A second upload with the
same key but different content returns `409 Conflict`.

There is no public list, delete, or overwrite endpoint. Assets can only be
read, not modified or removed, through the public API.

Clone the repository:

```bash
git clone https://github.com/dangkhoa2016/Huggingface-Models-Assets-Cloudflare-Worker.git
cd Huggingface-Models-Assets-Cloudflare-Worker
```

## Configuration

Deployment is configured in `wrangler.jsonc`. The R2 bucket binding and
environment variables are declared there:

```jsonc
{
  "name": "huggingface-models-assets-worker",
  "main": "src/worker.js",
  "r2_buckets": [
    { "binding": "ASSETS", "bucket_name": "huggingface-models-assets" }
  ],
  "vars": {
    "MAX_UPLOAD_BYTES": "16777216"
  }
}
```

- `MAX_UPLOAD_BYTES`: maximum upload size in bytes. Defaults to `16777216`
  (16 MiB) when unset or invalid.

**Note:** The checked-in `wrangler.jsonc` sets `workers_dev=false`. Deploying
this Worker does not create a public `workers.dev` endpoint. It is intended to
run as an internal backend accessed by the Stream Proxy through a Service
Binding. To expose it directly, explicitly enable `workers_dev` or configure a
Route / Custom Domain.

## Cloudflare secrets

The publisher secret `PUBLISH_TOKEN` is required for uploads. See the
Deployment section below for the recommended first-time provisioning
workflow. Do not store token values in source code, configuration files,
shell history, or logs.

## Initial provisioning

Install dependencies, verify locally, then provision Cloudflare resources:

```bash
npm install

npm run check
npm test
npm run deploy:dry-run

npx wrangler r2 bucket create huggingface-models-assets

npx wrangler deploy --secrets-file <secure-secret-file>
```

The secrets file can be JSON or `.env` format. Keep it outside the
repository and do not commit it. Example `.env` format:

```text
PUBLISH_TOKEN=<your-token-value>
```

`wrangler secret put` is also supported but is a deployment-affecting
operation that creates a new Worker version. Prefer `--secrets-file` for
first-time deployment to avoid an intermediate draft deployment.

## Deployment

### Standalone

This Worker can run independently. After provisioning, deploy with:

```bash
npx wrangler deploy
```

### With the Stream Proxy (Service Binding)

This Worker is the backend for the [Huggingface Stream Proxy](https://github.com/dangkhoa2016/Huggingface-Stream-Proxy-Cloudflare-Worker).
The companion project's `wrangler.toml` must declare a Service Binding:

```toml
[[services]]
binding = "ASSET_SERVICE"
service = "huggingface-models-assets-worker"
```

Deploy this storage Worker **first**, then deploy the Stream Proxy. Cloudflare
requires the target Worker to exist before deploying a caller with a Service
Binding.

## API

### `PUT /assets/hf/<owner>/<repo>/<commit>/<path>`

Authenticated immutable upload.

Required headers:

```text
Authorization: Bearer <PUBLISH_TOKEN>
Content-Length: <byte length>
X-Content-SHA256: <64 lowercase hex characters>
Content-Type: <asset media type>
```

Responses:

| Status | Meaning |
|--------|---------|
| `201` | Object created |
| `200` | Same key and same digest already exists (idempotent) |
| `400` | Invalid digest format, invalid `Content-Length`, or malformed path |
| `401` | Missing or invalid bearer token |
| `409` | Same key exists with different content |
| `411` | Missing `Content-Length` |
| `413` | Upload exceeds `MAX_UPLOAD_BYTES` |

### `GET /assets/hf/<owner>/<repo>/<commit>/<path>`

Public streaming read. Supports byte `Range` requests and conditional headers
(`If-Match`, `If-Unmodified-Since`, `If-None-Match`, `If-Modified-Since`).
`If-Range` is supported with an ETag validator: when the ETag matches the
current object the requested range is returned; when it does not match the
`Range` header is ignored and the full object is returned with `200`.

Conditional evaluation follows HTTP precedence: `If-Match` is evaluated
first; `If-Unmodified-Since` is evaluated only when `If-Match` is absent.
`If-None-Match` is evaluated next; `If-Modified-Since` is evaluated only
when `If-None-Match` is absent.

Responses:

| Status | Meaning |
|--------|---------|
| `200` | Full object streamed (or `If-Range` mismatch ignoring `Range`) |
| `206` | Partial content (byte range) |
| `304` | Not modified (`If-None-Match` / `If-Modified-Since`) |
| `404` | Asset not found |
| `412` | Precondition failed (`If-Match` / `If-Unmodified-Since`) |

### `HEAD /assets/hf/<owner>/<repo>/<commit>/<path>`

Public metadata read. Returns the same headers as `GET` with no response body.
Supports the same conditional headers as `GET` with identical precedence rules.

### `OPTIONS`

Returns CORS preflight headers. Allowed methods: `GET, HEAD, PUT, OPTIONS`.

## URL structure

Asset keys follow the path structure:

```text
/assets/hf/<owner>/<repo>/<40-hex-char commit>/<file-path>
```

Example:

```text
/assets/hf/zai-org/GLM-4-9B-0414/645b8482494e31b6b752272bf7f7f273ef0f3caf/config.json
```

The commit segment must be exactly 40 lowercase hexadecimal characters. Paths
containing encoded separators (`%2F`, `%5C`), dot segments (`.` or `..`), or
control characters (`\`, `\0`, `\r`, `\n`) are rejected.

## Local multi-Worker development

From the Stream Proxy directory, Wrangler can start both Workers together:

```bash
npx wrangler dev \
  -c wrangler.toml \
  -c ../Huggingface-Models-Assets-Cloudflare-Worker/wrangler.jsonc
```

R2 uses local emulated storage unless the binding is configured for remote
development.

## Publisher environment

The Python mirror tool sends uploads through the public gateway and reads the
token from an environment variable:

```bash
export R2_ASSET_PUBLISH_TOKEN='<same value configured as PUBLISH_TOKEN>'
```

Do not commit `.dev.vars` or any token-bearing file.

## Local tests

The test suite has no additional runtime dependency:


The tests cover PUT authentication, digest validation, upload size limits,
idempotency, conflict detection, GET streaming with metadata and CORS, byte
